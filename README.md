# Work Time: employee time tracking

A small, modern web application for tracking employees' working time in a company. Built from scratch with AI assistance as a test assignment, and designed to grow into a real multi-tenant product.

- **Live demo:** https://worktime.purcelalex.com (use the demo account details you were given; they are provided separately and are never stored in this repository)
- **Fictional data only.** Every name, task and time entry in the demo is invented.

## What it does

- **Add employees** (name, optional position).
- **Start, pause, resume and stop a timer** for an employee with a task description. Pausing stops the clock without losing the task; resuming continues from the time already worked. Stopping and starting again records a new, separate entry.
- **Delete an employee** (with a confirmation question). They leave the list, but their time records stay in the report history.
- **View records and total time per employee** for a chosen period (today, last 7 days, last 30 days, or a custom range), with a chart, totals, and the individual records.
- **Data is kept** after the application restarts: everything is stored in a database.
- Works well on a phone and on a desktop (installable as a web app), keyboard accessible, with a green and white design.

The assignment said authorization was not required. A login page was added deliberately, so each evaluator gets an isolated demo workspace and the app can later serve real organizations.

## Run it locally

Requirements: Node.js 22 or newer and npm.

```bash
npm install
npm run db:migrate:local   # creates the local database
npm run seed:demo          # creates 20 demo workspaces (writes their passwords to the git-ignored secrets/ folder)
npm run dev                # http://localhost:5173
```

Sign in with an account from `secrets/demo-credentials.md` (generated by the seed script on your machine).

Other commands:

```bash
npm test            # API and unit tests (Vitest on a real local D1 database)
npm run test:e2e    # end-to-end tests (Playwright, phone and desktop sizes, accessibility checks)
npm run typecheck
npm run lint
npm run build
```

The end-to-end tests use the installed Chrome and a local-only test account created by `npm run e2e:setup`. Deployment steps are in [docs/HOW_TO.md](docs/HOW_TO.md).

## Stack and why

| Part | Choice | Reason |
|---|---|---|
| Hosting | Cloudflare Workers with static assets | One deployable unit, global edge, nothing to patch |
| API | Hono (TypeScript) | Small and fast |
| Database | Cloudflare D1 (SQLite) with Drizzle ORM | Time reports are relational queries |
| Validation | zod (server side) | One strict schema per request |
| Frontend | React 19, Vite, Tailwind CSS 4, TanStack Query | Modern, fast, accessible |
| Tests | Vitest (API and unit), Playwright (end to end) | Real database, real browser |

Architecture, specification and security design are in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [docs/SPEC.md](docs/SPEC.md).

### Highlights

- **Multi-tenant by design:** every row carries an organization id and every query is scoped by it. Tests try to cross that boundary on every endpoint.
- **The server clock is the only clock:** start and stop times are set by the server, and live timers use the server's time offset.
- **One running timer per employee** is enforced by a database index, so even simultaneous requests cannot create two.
- **Security:** strict Content Security Policy with Trusted Types, HSTS and the other headers, host-only HttpOnly cookies, hashed session tokens, PBKDF2 password hashing, login rate limiting, no third-party scripts or fonts, and only the minimum personal data (a name and a task text).
- **Accessibility and mobile:** WCAG 2.2 AA checks with axe, keyboard use, bottom tab bar on phones, sidebar on desktop.

## Errors found and fixed in AI-generated code

These are real, found by tests, tooling or review (details in [docs/AI_LOG.md](docs/AI_LOG.md)):

1. **Deprecated test package** named in the specification: caught when `npm install` failed on a peer-dependency conflict; replaced with the current package.
2. **Login rate limit too strict for shared networks** (5 failures per IP would lock out a whole company): exposed while writing authentication tests; the IP limit is now 20 and the per-account limit stays at 5.
3. **The validation library broke the strict browser security policy:** zod probes for `eval` with `new Function`, which violated Trusted Types in the production build. Found by an end-to-end CSP check; fixed by keeping zod out of the browser bundle, which also cut the first-load JavaScript from 126 KB to 98 KB (gzip).
4. **Dialog focus bug:** React's `autoFocus` ran before the native dialog opened, so keyboard users landed on the close button. Found by the keyboard-only test; fixed.
5. **Unused dependency with known vulnerabilities** (`drizzle-kit`): found by `npm audit`; removed, leaving 0 vulnerabilities.

## Privacy and GDPR

- The demo contains **fictional data only** and says so on the login page, inside the app and in the public privacy notice (`/privacy`).
- Only the minimum is processed: account name, hashed password, hashed session token, and a short-lived IP-based login throttle. No analytics, no third-party scripts, one strictly necessary cookie.
- Expired sessions and throttling rows are deleted automatically every day.
- The demo runs in its **own isolated environment** (separate Worker and database). A production version for real organizations runs separately, so demo users can never reach real data.
- Engineering guidance (not legal advice): [docs/PRIVACY_GDPR.md](docs/PRIVACY_GDPR.md).

## Known limitations and next steps

- Report periods use the browser's time zone; per-organization time zones are planned.
- Time entries cannot be edited or deleted yet, and deleting an employee only hides them (a real erasure feature and an audit log come first).
- The demo uses password sign-in. Real accounts will use magic links and passkeys.
- The live deployment may include additional private administration modules that are not part of this repository.
